# 穿戴甲AIGC商品视觉生产管理系统用户操作说明书素材（草案）

软件全称：穿戴甲AIGC商品视觉生产管理系统  
软件简称：穿戴甲视觉生产系统  
版本号：V1.0

说明：本草案只描述当前代码实际存在的功能。页面源码仍显示内部历史技术标识 `Lunelle Studio`；源码中的 `FINGLOW` 与 `api.finglow.cn` 属于客户项目历史部署标识。本轮仅整理软著材料，没有修改页面或任何真实项目源码。

## 1. 软件概述

穿戴甲视觉生产系统是一套面向穿戴甲商品视觉内容生产的浏览器/服务器软件。操作员可以建立款式和 SKU，上传参考图或 2×5 十甲款式图，创建商品图、佩戴图、上架主图和多肤色多视角试戴图生成任务，查看任务状态和结果，处理失败或修正任务，完成人工审核，并导出或发布审核通过的图片资产。

软件把每一次生成保存为持久任务，记录 Prompt 版本、模型、输入快照、尝试次数、错误、费用、QA 和人工审核状态。重新生成或修正会产生新任务/新版本，不覆盖已有成功结果。

## 2. 开发目的

软件用于把穿戴甲商品视觉内容制作中的款式录入、AI 图片生成、批量任务管理、质量检查、人工确认、费用控制、素材导出和试戴发布整合为可追踪的生产流程，降低零散使用图片生成工具时出现的重复调用、设计漂移、状态不可见和结果不可追溯问题。

## 4. 系统总体架构

系统由原生 Web 管理页面、FastAPI REST 服务、任务服务、SQLite 数据库、进程内 Worker、AI Provider、自动 QA、本地素材存储以及可选的 Cloudflare R2/D1 发布模块组成。

操作员在页面发起请求后，后端创建任务并写入 SQLite。Worker 线程从数据库原子领取任务，验证输入快照和预算后调用外部 AI 图片接口。成功结果先保存到本地，再进入自动 QA 和人工审核。审核通过的结果可以导出为 Shopify 素材包，或发布到线上试戴存储。

## 5. 软件主要功能

- 款式与 SKU 建档。
- 从文字描述或图片创建款式。
- 参考图、2×5 款式图和十甲身份管理。
- 2×5 款式图自动切分、人工调整和版本审核。
- 商品图、佩戴图、上架主图生成。
- 4 肤色 × 4 视角试戴矩阵生成。
- 任务队列、状态筛选、失败重试、取消。
- 自动 QA、视觉 LLM 建议、人工批准/拒绝。
- 候选版本对比、候选选择和修正任务。
- 任务、成功率、失败、费用和 QA 统计。
- 审核后素材导出和可选 Cloudflare 发布。

## 6. 登录/进入系统

当前代码没有用户注册、用户名/密码登录页、角色或多租户系统。

当服务端没有配置管理员令牌时，操作员可直接打开系统页面。当服务端设置了 `LUNELLE_ADMIN_TOKEN` 时，写操作必须携带相同的管理口令：

1. 打开“设置”页面。
2. 在“管理口令”输入框中填写管理员提供的口令。
3. 输入框内容变化后，页面把口令保存到当前浏览器的 localStorage。
4. 后续写请求自动携带 `X-Admin-Token`。

管理口令只保存在当前浏览器；页面没有独立“登录”或“退出登录”按钮。清除浏览器站点存储可移除本地口令。

## 8. 商品/SKU 管理

### 8.1 从描述创建

1. 进入“新建款式”。
2. 保持“从描述创建”标签。
3. 输入中英文款式描述。
4. 可填写名称、甲型和长度；名称可留空由系统生成。
5. 可选上传图片，并指定为“2×5 款式图”或“参考图”。
6. 点击“创建并出图”会创建款式并排队 Grid/Wearing 任务；点击“仅创建”只建立款式。

系统根据输入生成唯一 SKU。若指定 SKU 已存在，后端拒绝重复写入。

【截图：从描述创建款式页面】

### 8.2 按图识别创建

1. 切换到“按图识别”。
2. 选择图片类型：2×5 款式图或成品/风格参考图。
3. 选择 PNG、JPEG 或 WEBP 文件。
4. 系统调用已配置的视觉 LLM 识别颜色、元素、甲型等字段，创建款式。
5. 如果上传的是款式图，系统会尝试识别逐甲身份；失败时页面提示后续人工补写。

没有配置 LLM 通道时，按图识别不能完成。

在款式卡片点击“管理”，可以查看名称、SKU、甲型、长度和基础颜色，并管理素材、切图、线上试戴编号和十甲身份文本。

## 9. 素材上传与管理

### 9.1 图片上传规则

- 支持 PNG、JPEG、WEBP。
- 后端验证真实图片格式和最大文件大小。
- 用户原始文件名不会直接作为服务器文件名。

### 9.2 款式图与参考图

在款式管理弹窗中点击“上传/替换款式图”或“上传/替换参考图”。

- 款式图是 2×5 十甲设计权威，试戴矩阵需要它。
- 参考图用于商品图/风格参考，不会自动替代缺失的款式图。
- 替换款式图后，系统会重新尝试切分和逐甲身份识别；已排队任务仍依据其创建时快照执行，不随新素材静默改变。

### 9.3 款式图切分

上传款式图后，可点击“自动切分”。系统检测十个甲片框并生成检测预览、Contact Sheet、置信度和门禁原因。

- 自动通过：可作为后续视图计划的切图版本。
- 等待人工检查：操作员查看预览后选择确认或拒绝。
- 人工调整：在 Canvas 中选择甲位，拖动或输入坐标调整框，保存后创建新的人工版本，不覆盖旧版本。

## 10. AI 生成任务创建

### 10.1 批量出图

在款式卡片点击“批量出图”，系统以 Batch 模式创建 Grid 商品图和 Wearing 佩戴图任务。相同成功任务不会重复生成；需要新版本时通过后端 `force=true` 或修正流程创建新任务。

### 10.2 精修主图

点击“精修主图”，系统以 Precision 模式创建 Hero 上架主图任务。Precision 策略关闭自动创意修复，保留更多人工控制。

### 10.3 试戴矩阵

1. 确保款式有 2×5 款式图、可用切图版本、逐甲身份和所需手模底图。
2. 点击“试戴”。
3. 系统先免费计算将生成的图片数量、已有结果、进行中数量、预计费用、最坏费用上限和 24 小时预算。
4. 操作员确认费用上限后，页面把同一上限回传作为授权值。
5. 若报价在确认与提交之间变化，后端拒绝旧授权并要求重新确认。

默认完整矩阵为 4 种肤色 × 4 个视角，共 16 个单元；已有成功或进行中的单元不会重复排队，除非明确强制新版本。

## 12. 任务状态查看

点击任务行可打开任务详情。代码中的任务状态含义如下：

| 状态 | 含义 |
|---|---|
| pending | 已入队，等待 Worker |
| running | Worker 已领取并执行 |
| retrying | 遇到可重试错误，等待下一次计划时间 |
| success | 图片已成功保存；仍需查看 QA/人工审核状态 |
| failed | 不可重试、超过重试次数或依赖失败 |
| cancelled | 操作员取消了尚未执行的任务 |

任务详情可显示结果图、Prompt/版本、错误、尝试记录、QA、人工审核、候选谱系和修正操作。成功状态不等于已经允许导出/发布。

## 13. 失败任务处理

### 13.1 自动重试

超时、网络、DNS、限流、服务端错误、下载失败和服务中断属于可重试错误。系统按指数退避等待，并在最大次数内自动重试。

认证失败、请求参数错误、内容策略、非法响应、写盘失败、配置错误、不安全 URL、依赖缺失、预算超限、依赖失败和快照不匹配不会盲目自动重试。

### 13.2 手动重试

失败或已取消任务可点击重试。手动重试会清除旧错误、重置自动重试次数，并对允许重新规划的任务按当前素材重新冻结输入快照。成功任务不能用“重试”原地覆盖。

### 13.3 取消

只有 pending 或 retrying 任务可以取消。running、success、failed 任务不能通过该操作取消。

### 13.4 依赖失败

如果 Grid 等依赖任务最终失败或取消，等待它的 Wearing/下游任务会被标记为 dependency_failed，不会缺少参考图仍继续付费生成。依赖任务后来手动重试成功后，仅因 dependency_failed 而失败的下游任务可被重新排队。

## 14. 生成结果管理

### 14.1 自动 QA 与人工审核

图片成功落盘后自动执行本地 QA。自动 QA 完成后，任务进入等待人工复核。可选视觉 LLM 的结论只是建议，不能代替人工批准。

操作员在任务详情中查看 QA 问题和建议，选择批准或拒绝。重新运行 QA 会撤销旧的审核结果，要求重新人工确认。

【截图：任务 QA 与人工批准/拒绝区域】

### 14.2 候选对比与选择

同一 root lineage 下的成功版本显示在候选工作台。页面可选择两个候选进行图片对比，并把一个成功候选标记为当前选择。候选选择和人工批准是两个不同动作：选中“最好的一版”不等于允许发布。

【截图：候选版本对比工作台】

### 14.3 提交修正

在成功任务详情中输入明确修正内容，可选择目标甲位并可选上传补充图片。提交后系统以当前成功图为基础创建新的修正版本，不覆盖原图。

如果视觉 QA 返回了明确修正文本和目标甲位，页面可执行“一键修正”；它仍然创建新任务，并受自动谱系预算限制。

【截图：提交修正区域】

### 14.4 导出素材包

在生成队列点击“导出素材包”。系统只导出通过机器 QA 且经过人工批准的合格结果，输出目录包含：

- WebP 图片；
- `manifest.json`；
- `products.csv`；
- `generation-report.csv`。

不满足门禁的款式会被跳过并显示原因。

【截图：导出素材包操作及结果提示】

### 14.5 发布到线上试戴

在款式管理中填写三位试戴编号，检查“可发布单元”数量。点击发布前页面要求确认。发布流程把图片先上传到 Cloudflare R2，再更新 Cloudflare D1 记录；本地保存发布版本、进度和失败记录。

只有成功、QA 完成且人工批准的矩阵单元可以发布。Cloudflare 未配置时不能发布。

## 17. 异常处理

| 异常场景 | 系统行为/操作建议 |
|---|---|
| 管理口令无效 | 写接口返回 401；在设置页检查当前浏览器保存的口令 |
| 图片格式/大小不符 | 上传被拒绝；改用有效 PNG/JPEG/WEBP 并控制文件大小 |
| 未配置图片通道 | 服务启动校验失败或任务配置错误；由管理员配置通道 |
| 未配置 LLM 通道 | 按图识别/身份识别不可用；普通确定性款式创建仍可使用 |
| 缺少款式图、切图或手模 | 矩阵任务被阻止，不调用付费 Provider；补齐后手动重试/重新排队 |
| 超出 24 小时预算 | 新调用被预算断路器拒绝；等待窗口滚动或由管理员调整预算 |
| 快照与实际输入不一致 | 任务以 snapshot_mismatch 失败，不调用 Provider；检查素材/通道变化后重新规划 |
| 网络/限流/服务错误 | 自动进入 retrying 并按指数退避重试 |
| API Key 无效 | 任务以 auth_invalid 失败；更新通道后手动重试 |
| 服务执行中重启 | running 任务按 interrupted 恢复并进入受限重试；未完成本地 QA 会重新执行 |
| QA 失败 | 查看问题、拒绝结果、提交修正或生成新候选 |
| 发布部分失败 | 本地发布账本记录 planned/uploading/uploaded/failed 及进度；修复配置后重新发布 |

## 18. 软件退出/结束

当前管理页面没有“退出系统”按钮。结束浏览器操作可以直接关闭页面或浏览器。若配置了管理口令，要清除当前浏览器保存的访问凭据，可清除该站点的 localStorage/站点数据。

停止服务的方式由部署方式决定：

- 前台本地进程：由服务管理员终止进程。
- Docker Compose：由服务管理员执行停止操作；持久卷中的数据库和文件保留。

普通业务操作员不应直接停止服务、删除数据目录或修改 SQLite 数据库。
